# Bocha Switcher — план разработки

> Документ для Claude Code в VS Code. Положи его в корень репозитория как `PLAN.md` (или `CLAUDE.md`) и дай Claude команду: «Прочитай PLAN.md и начни с Фазы 0».

## Цель

Нативное macOS-приложение **Bocha Switcher** — аналог Punto Switcher: исправляет текст, набранный не в той раскладке (`ghbdtn` → `привет`), по хоткею и автоматически. Живёт в меню-баре, распространяется как `.dmg`.

**Основа:** форк [rashn/RuSwitcher](https://github.com/rashn/RuSwitcher) (лицензия MIT, Swift 6 + AppKit, macOS 13+, universal binary).

**Резервный вариант:** [graninilya/keyswitcher](https://github.com/graninilya/keyswitcher) (тоже MIT) — у него сильнее автодетектор (словари hunspell + n-граммы). Логику детектора можно позже перенести оттуда.

**Не использовать:** код `open-switcher` (GPL-3.0, запрещает закрытые/платные форки) и `rshagiev/punto-switcher` (лицензия не подтверждена).

## Фаза 0 — Подготовка окружения (≈15 мин)

1. Проверить, что установлены Xcode Command Line Tools: `xcode-select -p`. Если нет — `xcode-select --install`.
2. Проверить версию Swift: `swift --version` (нужен Swift 6).
3. Форкнуть RuSwitcher в свой GitHub-аккаунт, репозиторий назвать `bocha-switcher`.
4. Клонировать форк локально и открыть в VS Code.
5. Если на Маке установлены RuSwitcher или Punto Switcher — выйти из них (конфликт event tap).
6. **Сразу собрать оригинал без изменений:** `bash build_app.sh` — убедиться, что сборка проходит, до того как что-то трогать.

**Готово, когда:** оригинальный RuSwitcher.app собирается и запускается.

## Фаза 1 — Аудит кода (≈30 мин)

Задача для Claude: пройтись по репозиторию и составить список всего, что нужно поменять. Отдельно проверить:

- `macos/` — основной код, Info.plist, bundle ID, строки с именем «RuSwitcher».
- `version.json`, `version-beta.json` — **механизм автообновлений смотрит в репозиторий автора**. Это критично: без замены наше приложение будет предлагать обновиться до RuSwitcher.
- `stats/`, `telegram/` — понять, что это (статистика? бот?) и есть ли там сетевые вызовы. Всё, что уходит в сеть на чужие серверы, — удалить.
- `.github/workflows/` — CI автора (подпись, релизы, Homebrew tap).
- `windows/`, `shared/` — Windows-версия нам не нужна.
- Ссылки на Boosty, донаты, контакты автора в окне «О программе».
- Локализации (16 языков) — где хранятся строки с названием.

**Готово, когда:** есть чеклист файлов и строк на замену.

## Фаза 2 — Ребрендинг (≈1–2 часа)

1. **Название:** `RuSwitcher` → `Bocha Switcher` в UI, `BochaSwitcher` в именах файлов и таргетов.
2. **Bundle ID:** заменить на свой, например `help.501c3.bochaswitcher`.
   - Важно: разрешения Accessibility и Input Monitoring в macOS привязаны к bundle ID — после смены их придётся выдать заново.
3. **Автообновления:** перенаправить на свой репозиторий (`version.json` в нашем форке) или временно отключить.
4. **Окно «О программе»:** своё название, версия 1.0.0, убрать донаты автора.
5. **Лицензия:** сохранить `LICENSE` с копирайтом rashn (требование MIT) и добавить свою строку. В «О программе» — строка «Основано на RuSwitcher (MIT)».
6. Удалить `windows/`, чужие workflows и всё, что найдено в аудите как лишнее.
7. Локализации: оставить русский и английский, остальные можно убрать ради простоты.

**Готово, когда:** в коде и UI не осталось упоминаний RuSwitcher, кроме лицензии и строки об авторстве.

## Фаза 3 — Иконка и бренд (≈1 час)

1. **Иконка приложения** (`.icns`): сделать из PNG 1024×1024 через `iconutil`.
2. **Иконка меню-бара:** монохромная, показывает «Б» / «B» в зависимости от раскладки (в RuSwitcher уже есть монохромный режим РУ/EN — адаптировать его).
3. **Пасхалка на экране приветствия:** анимация `ищсрф` → `bocha` (набор «bocha» в русской раскладке). Добавить в онбординг.

## Фаза 4 — Сборка DMG (≈30 мин)

1. Собрать universal binary (Apple Silicon + Intel).
2. Ad-hoc подпись: `codesign --force --deep --sign - BochaSwitcher.app`.
3. Создать DMG с ярлыком на «Программы»:
   - простой вариант — `hdiutil create`;
   - красивый — `create-dmg` (`brew install create-dmg`) с фоном и расположением иконок.
4. Итоговый файл: `BochaSwitcher-1.0.0.dmg`.
5. Добавить скрипт `scripts/make_dmg.sh`, чтобы следующие сборки делались одной командой.

**Готово, когда:** DMG открывается, приложение перетаскивается в «Программы» и запускается.

## Фаза 5 — Тестирование (≈1 вечер, дальше по ходу использования)

Проверить исправление по хоткею и автоисправление в:

- Safari, Chrome
- Telegram, Slack (Electron)
- VS Code (Electron-редактор)
- Terminal / iTerm
- Notes, Mail, Pages
- поля паролей — приложение **не должно** в них срабатывать.

Отдельно: откат (повторное нажатие), выделенный текст, слова с `,.;:` на конце, короткие слова.

## Фаза 6 — Распространение (когда будет готово для других)

Без подписи Apple пользователи при первом запуске увидят предупреждение «неизвестный разработчик» (открывается через ПКМ → «Открыть»). Для нормальной раздачи:

1. Apple Developer Program — $99/год.
2. Подпись сертификатом **Developer ID Application**.
3. Нотаризация через `xcrun notarytool`.
4. GitHub Actions на macOS-раннере: автоматическая сборка, подпись и выкладка DMG в Releases по тегу.
5. Опционально — свой Homebrew tap.

## Правила для Claude Code в этом проекте

- Перед каждой фазой — показать план изменений, после — собрать и убедиться, что сборка проходит.
- Не отправлять никакой текст пользователя в сеть. Никакой телеметрии.
- Сохранять совместимость с macOS 13+ и universal binary.
- Коммит после каждой завершённой фазы с понятным сообщением.
